# v6 改版計畫：平台核心

照 [DESIGN.md](DESIGN.md) 把平台核心做成可以單機玩一整輪的版本。v5 原封不動留著，當作東恆村規（難題融合拆解）的參考實作。

## 原則

- 新資料夾 `v6/`，不動 `v4/`、`v5/`。
- 規則與資料一層（純函式，node 可測），畫面一層；世界只能是資料。
- 單機：所有角色存在本機，用「我是」切換角色測整個流程。多人連線、資料三層存放、簽章、驗證碼都是之後的事，但資料格式先留好欄位。
- 介面全部繁體中文，手機優先。

## 從 v5 沿用

| v5 | v6 |
|---|---|
| `world.js`（Three.js 場景、走路、繞圈、傳送門、內部空間、標籤） | 直接沿用，只改功能點清單 |
| `data.js` 的序號、代號、走法解碼、`cleanWorld`、外觀形體 | 沿用；角色資料格式改寫 |
| `sheets.js` 活頁簿（欄字母、列號、凍結首欄、跳轉、返回、下一步） | 沿用機制，頁面全部換成新的 |
| `fusion.js`、`exchange.js`、難題、題點戰點、熱量 | **不搬**，留在 v5 當村規參考 |

## 資料格式（`v6/src/core.js`）

```
role = {
  serial, name,
  dailyPoints,                 // 每天產生的點，預設 1800–2000，可自訂
  life: { startUs, endUs },    // 生命週期（微秒）
  state: 'active' | 'vacancy' | 'ended',
  prev: serial | null,         // 改規則而重創時，指向前一個角色
  rules: {
    uses: [文字],              // 我的點能做什麼
    conditions: [{ field, op, value }],
    bothMustPass: false,
    mustAcceptVillage: false,
    village: 文字,             // 村規，誰寫的誰解釋
    villageKey: null           // 村規網站公開金鑰（之後做驗證碼用）
  },
  rulesHash,                   // 創建時算出，週期內規則不能改
  resources: [{ id, name, price, qty }],   // price 以本角色的點計
  slots: [{ id, atUs, capacity, bookings: [serial] }],
  contact: 文字,               // 只給預約成功的人看
  world: { objects, walk, start, path }    // 沿用 v5 格式，功能換成新清單
}
points  = [{ id, issuer, holder, amount, docking, atUs, spent, sig: null }]
dockings = [{ id, a, b, atUs, slot, gaveA, gaveB }]
redeems = [{ id, holder, issuer, resource, cost, atUs, ok }]
acceptances = [{ who, of }]    // 誰接受了誰的村規
```

## 規則（純函式，每條都要有 node 測試）

1. **每天的點**：`remainingToday(role, day)` = `dailyPoints` − 今天已給出的；本機日期換日歸零；不能預支。
2. **生命週期**：週期外角色是 `ended`，他的點全部作廢；規則一律不能改（改就要結束、以 `prev` 重創）；提早結束要先確認沒有未兌現的點，或持有人都同意。
3. **條件判定**：`passes(owner, visitor)` 依 `conditions` 算；`eligible(a, b)`：一方通就可以；任一方 `bothMustPass` 就要兩方通；任一方 `mustAcceptVillage` 而對方沒接受就不行；空窗角色自己的條件與兩個開關都視為關閉，只能以「做不到對方要求」拒絕。
4. **條件欄位（第一版）**：對方每天的點數、對方週期還剩多久、對方狀態、對方手上有多少我的點、對方對接過幾次。
5. **查詢**：`canVisit(me)`（我符合誰）、`canCome(me)`（誰符合我）、`searchResources(keyword)`；排序只照事實。
6. **預約**：條件通才能預約；名額滿就不行；空窗角色照樣有名額。
7. **對接**：時段那一微秒，預約者站在主人的終點上就成立；雙方各填要給多少（不超過當天剩下的）；寫入 `dockings` 和 `points`。
8. **兌現**：持有人用主人的點照資源表價格換；主人空窗時暫停；`qty` 不足 = **兌現失敗** → 主人自動進入空窗；補足資源並兌現那一筆後自動解除。
9. **空窗**：手動進入 / 離開；空窗中每天的點停發、別人手上的點暫停兌現、週期時鐘照走。

## 3D 裡世界

- 功能點換成：**規則（屋）、資源（市集）、終點（台）、角色（碑）、點數（帳房，只有自己看得到）、地標**。
- 靠近規則建築看得到：我的點能做什麼、對接條件（用白話顯示，例如「每天的點數 ≥ 1000」）、村規、兩個開關。這是裡世界存在的理由，要做得最清楚。
- 終點顯示對接時段和名額；靠近時可以預約。那一微秒站在上面就對接。
- 走代號、傳送門、內部空間沿用 v5。

## 表世界（活頁簿）

**下一步｜查詢｜角色｜規則｜資源｜世界｜走法｜對接時段｜對接紀錄｜點數｜兌現**

- **下一步**：①建角色（每天的點、週期）②寫規則與條件 ③資源 ④世界與走法 ⑤開對接時段 ⑥去查詢、預約別人。
- **查詢**：「我可以去找的人」「可能來找我的人」兩張表，加資源關鍵字搜尋；每列有「看規則」「傳送過去」「預約」。
- **規則**：條件用下拉選欄位與比較，數值自己填；週期內鎖住不能改，只有「結束並重創」按鈕。
- **點數**：我手上的別人的點（照發點的人分組、到期日、能不能兌現）、我今天還剩多少點可給。
- **兌現**：選發點的人、選資源、兌現；失敗會說明主人已進入空窗。

## 預設示範資料

三個角色，條件設計成：J1 和 J2 一方通、J2 和 J3 要兩方通但不通、J3 要求接受村規。至少一個角色有資源數量 1，方便測兌現失敗 → 自動空窗。

## 測試

- node：每天的點與歸零、生命週期與作廢、提早結束、條件判定（一方通、兩方通、村規開關、空窗）、查詢、預約名額、對接寫帳、兌現與兌現失敗自動空窗。
- 瀏覽器（Playwright）：走代號傳送、看規則建築、預約、那一微秒對接、兌現、活頁簿各頁與跳轉。

## 這一版不做

多人連線、三層資料存放、簽章、村規驗證碼的實際驗證、聯絡方式加密、紙條與動作交流。
