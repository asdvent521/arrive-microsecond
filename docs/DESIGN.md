# 到達那微秒：v5 設計定案

整理日期：2026-09-29。這份文件記錄 v4 之後重新整理、已經定案的設計。v4 的程式還是舊設計（一對多、人生行事歷），v5 會照這份文件改。

## 一句話

用現實中的難題當關卡的合作遊戲。自己想不出辦法的難題，要在約好的那一微秒遇到另一個角色，把兩個難題融合、拆解、分工，直到能算出往後要付出多少熱量。

## 核心定義

- **難題**：原本的角色自己想不出辦法的情況。自己想得出來的，不算難題。
- **完成（可處理）**：能算出往後需要的熱量。每個參與的角色都填完熱量，才算完成。

## 流程

1. **創角色、立難題**：寫下出發點，也就是預定開始處理的時間，精確到微秒。立難題就代表自己想不出辦法。
2. **碰撞**：另一個角色帶著類似的難題，指定對方的代號（見「角色序號」），並寫下同一個出發點。在那一微秒到達，兩邊撞上就融合。代號決定去找誰，出發點決定什麼時候見。
   - 單機：自己開新角色，指定舊角色的代號、寫同一個時間。
   - 熟人：知道對方的代號和常用尾數，就對得上。
   - **到達就成立，不判斷類似**：來的人一路經過對方的難題，走到終點就代表他判斷過類似。硬湊的組合拆不出辦法，到期限自然擱置。
   - **同一微秒來幾個就融合幾個**：能在那一刻出現的人都知道代號和精確時間，等於都是熟人。三個難題一起融合，就像解三元一次方程式。
3. **融合與拆解**：像解二元一次方程式，難題融合成新難題，再拆成幾個階段的挑戰。融合後所有參與者都能構思。
4. **分工**：
   - 構思者得題點，由其他參與者各發一份。階段經全員同意時就發出。
   - 執行者得戰點，判定完成時發出，戰點每個人都可能拿到。
   - **每筆題點、戰點都記下發出者、拿到的人、當時的規則版本**（點數比例的版本）、對應的融合與階段、發出時間，還有發出者的簽章欄位。原型先不做兌換，但格式先定好：`{id, kind, from, to, amount, atUs, fusion, stage, ruleVersion, sig}`。
   - 新增或修改階段要全員同意。
5. **判定**：至少雙方共判。**有人判未完成，階段就變「爭議」**；爭議要全員同意才能改判完成，或退回執行中；意見不一致就一直是爭議。
6. **完成**：**所有階段都判定完成後才能填熱量**；每個角色填入熱量，全部填完才算可處理。
7. **每個出發點都是一個關卡**：那一微秒不是見面就是擱置。
   - 融合時，參與者約好下一個出發點，這就是融合難題的期限。
   - 到了下一個出發點：
     - 已經可處理：完成。
     - 還沒可處理，但有人來：加入融合，約下一個出發點。**融合約好下一個出發點後，每個參與者的出發點都是同一微秒，非參與者到「任何一位參與者的終點」就算有人來。只有參與者自己站在終點，不算有人來，一樣擱置。**
     - **融合還沒約好下一個出發點時（剛相遇、或有人加入後），只能約出發點；不能提階段、不能執行。**
     - 還沒可處理，也沒人來：擱置。
   - 出發點那一微秒一個人都沒來：原難題擱置。
   - 擱置：留下紀錄，必須重創難題（新難題、新出發點，可註明前身）。融合難題擱置時，所有原難題也跟著擱置。
8. **三方以上**：題點通用。A 構思一個階段，B、C 各付一份，A 可以換 B 或 C 的能量點。
9. **退出**：角色可以中途退出，不懲罰，只留紀錄。
   - 已發出的題點、戰點照舊有效，事後不能取消。
   - 退出者執行到一半的階段變回沒人負責，不發戰點。
   - 退出者構思、還沒開始的階段留著，別人可以接手執行。
   - 融合難題留給其他參與者，期限不變。
   - 退出者那一方的紀錄標為「退出」，跟「擱置」分開。
   - 退出逃不掉題點：題點在階段被全員同意時就已經發出。

## 角色序號

- 固定 11 位數，最多 10,000,000,000 個角色。系統第一個角色是 00000000001。
- 縮寫：開頭有幾個 0，就用第幾個英文字母取代。

| 序號 | 開頭 0 的數量 | 縮寫 |
|---|---|---|
| 00000000001 | 10 | J1 |
| 00000000010 | 9 | I10 |
| 00000000100 | 8 | H100 |
| 01000000000 | 1 | A1000000000 |
| 12345678901 | 0 | 12345678901 |

字母同時告訴你後面有幾位數，所以不會混淆。

## 裡世界：走出代號、傳送

- 每個角色在自己的世界擺放功能點和地標（外觀自由），並自訂**走法**：
  - 繞某個物件一圈是 J，繞兩圈是 I……
  - 從甲走到乙是 1，走到丙是 2……
- 要去找誰，就在自己的世界用自己的走法走出對方的代號。
- 走完出現**白光傳送門**，傳送到對方設定的路上，走到他設定的終點。沿途可以看他的規則。
- **任何時候**都能傳送過去逛；只有在他的出發點那一微秒抵達終點，才能見面、融合。代號是地址，微秒是約定。
- 表世界不用走：直接輸入代號（例如 J1）。走法表、功能點表在表世界先填好，裡世界照表蓋。

## 功能點（功能固定，外觀自由）

每張表在裡世界是一個**功能點**。功能是固定的，外觀完全由主人決定：規則不一定是屋子，可以是一棵樹、一台車、一座噴泉；難題不一定是碑，可以是一口井、一扇門、一團霧。名稱也由主人取。

來訪者靠近某個物件時，才會顯示它是什麼功能（例如「這裡是規則」），所以外觀再怎麼變，都找得到。

| 功能 | 對應的表 | 來訪者看得到嗎 | 預設外觀（可改） |
|---|---|---|---|
| 規則 | 規則表、規則版本 | 依可見條件 | 屋 |
| 難題 | 難題表（擱置的也留著） | 依可見條件 | 碑 |
| 終點 | 出發點 | 看得到 | 台 |
| 融合 | 融合紀錄 | 只有參與者 | 殿 |
| 階段 | 階段 | 只有參與者 | 工坊 |
| 熱量 | 熱量表、每日額度 | 只有自己 | 爐 |
| 點數 | 點數紀錄 | 只有自己 | 帳房 |
| 兌換 | 兌換紀錄、每日額度 | 兌換雙方 | 市集 |
| 紀錄 | 出發紀錄、擱置紀錄 | 只有自己 | 館 |
| 尾數 | 常用尾數 | 只有自己 | 密室 |
| 待處理 | 待處理 | 只有自己 | 信箱 |

- 外觀的資料：形狀（由基本形體組合：方塊、圓柱、球、錐……）、大小、顏色、位置、名稱。一個功能點可以由好幾個形體組成。
- 外觀隨時可以改（例如熱量從爐改成屋或樓），資料不受影響。走法表記的是「哪一個物件」，不是它的外觀，所以改外觀、變大、搬位置，代號照樣有效。
- 外觀也可以只是地標、沒有功能：例如一座純裝飾的山，只拿來繞圈走代號。
- 路就是路徑圖；傳送門走完代號才出現。功能點和地標都能當走法的地標。
- 原型先做五個功能點：規則、難題、終點、融合、階段。

### 內部空間（v5 已做）

- 外部和內部都自由構建：同一套工具、同一種資料格式。外部是來訪者一到就看見的風景，內部是走進門才看得到的空間。
- 任何物件都能設一扇門，走進去換到它的內部場景。內部一樣用基本形體蓋（地板、牆、樓梯、傢俱、地標），也能再放門通往更深的房間。
- 功能可以放在內部，例如規則掛在牆上的畫框裡、階段是工坊裡的工作台。
- 新手一個物件就是一個功能點；進階玩家才加門和內部。差別只在資料有沒有填內部那一欄。
- 可見條件管得到門：看不到的人走到門口只看到門關著。
- 內部也能繞圈、走路線，代號可以藏在房子裡。
- 限制：每個世界、每層內部有形體數量上限；巢狀最多 3 層；進門時只載入那一層，外面暫時不畫。
- 資料：`objects[].door = { visible, start: [x, z], objects: [...] }`；`visible` 用可見條件（所有人／融合過的人／只有自己），看不到的人靠近只看到「有一扇門，關著」。內部物件的代號和外部共用同一個命名空間，走法表可以指到內部物件，繞圈、走到在內部一樣算。

## 表世界：活頁簿

表世界是一本活頁簿，一張表一頁，下面是可以左右滑的分頁列。順序：

**下一步｜角色｜難題｜規則｜世界｜走法｜出發點｜融合｜點數｜兌換｜紀錄**

- **下一步**：依目前狀態列出 ①角色 ②難題 ③規則 ④世界 ⑤走法 ⑥出發點 的完成狀況，標出下一步，每項有按鈕跳過去；進入融合後，接著列 ⑦約下一個出發點 ⑧拆階段 ⑨執行與判定 ⑩熱量。
- 每一頁最下面有「下一步 →」按鈕；在「下一步」頁它跳到標出的那一步，在其他頁跳到下一張表。
- 每一頁都是 Excel 格式（沿用 v4 的活頁簿）：欄字母列、列號、凍結首欄、名稱方塊與編輯列（點格子會顯示 `Ⅰ!C2` 和內容）、最下列「＊」是新增列、連結跳轉與返回。「下一步」、規則比例、規則版本、融合、階段也都是表格；按鈕放在格子裡。
- 表與表之間的代號、難題、功能點、走法、階段、融合、規則版本都能點擊跳到對應那一列（跳到後那一列會閃一下）。
- **規則頁**是真的規則表：規則條目可增刪、每條設公開／只有自己；點數比例（1 題點、1 戰點各換多少大卡能量點）和資源欄；按「儲存成第 N 版」產生新版本，歷史版本列在下面。點數紀錄的 `ruleVersion` 記的是發出者當下的規則版本號，點數頁直接算出可換多少大卡。看別人的規則時只看得到公開的條目。
- **難題頁**：立難題、看狀態（進行中／融合中／擱置／退出／可處理）、設誰看得到、擱置的可以「以此為前身重創」。一個角色同時只有一個進行中的難題。
- **兌換頁**：手上的點數（照發出者、種類分組，值多少大卡、發出者今天剩多少額度）、換能量（選幾點）、換資源（選一項，點數不夠會擋）、今天的額度表、兌換紀錄。裡世界靠近「兌換」功能點（預設外觀市集）會顯示同樣的摘要和「打開兌換」。
- **世界頁**：每個物件有「門」欄（沒有門／門：所有人／融合過的人／只有自己），有門就能「進去編輯」它的內部，麵包屑顯示在第幾層；第 3 層不能再開門。

## 維護方式：玩家自己維護

- **不審核**：世界壞了，別人就不來，合作意願自然下降。
- 點數綁定發出者，只能換發出者的能量點；自己發給自己的點數沒有價值，作弊只騙到自己。
- 只有兩件事要做對，都由程式自動檢查：
  1. **共同格式與簽章**：大家用同一種資料格式；每筆點數有發出者的簽章，沒人能冒用別人發點數。
  2. **世界只能是資料，不能是程式**：傳送過去時只讀對方的資料（表格、功能點外觀、走法、規則），畫面由自己的程式畫，對方的程式碼永遠不在你的裝置上跑。
- 每個世界可以把快照放在主人自己的雲端空間，主人不在線也能逛；只有見面、融合需要雙方在線。
- 玩家可以用自己的 AI（自己的 API key）蓋世界、修東西，費用由玩家自己付。

## 技術與規模

- 不做 3A，做 **3D、小規模、手機和 Steam 都能玩**。參考《風之旅人》《Sky 光遇》《紀念碑谷》：範圍小、把相遇的瞬間做到極致。
- 引擎：**Three.js（網頁 3D）**。手機點連結就能測；之後包裝成 Steam 版和手機 App，不用重寫。
- 規則與資料是獨立的一層，畫面是另一層；換引擎只換畫面。

## 原型實作備註（v5 灰盒）

原型照上面的設計做，幾個實作上的決定記在這裡，之後定案有變再改：

- **繞圈怎麼算**：走進物件周圍一圈的範圍（半徑 + 3）開始累計轉過的角度，滿一圈算一圈；走出範圍才結算成字母。手機上一點一點走圈太累，靠近有走法的物件時多一顆「繞一圈」按鈕，按了自動排一圈路徑點，判定和自己走一樣。
- **走到怎麼算**：走到物件邊上（半徑 + 1）算到達。走法表的「從甲走到乙」看的是上一個到達的物件和這次到達的物件。
- **那一微秒怎麼到**：瀏覽器拿不到真的微秒，出發點存成微秒、時鐘顯示到微秒。判定用「站在對方的終點上，出發點那一微秒經過時人還在上面」就算到達；經過時不在上面就擱置，留紀錄。原型的出發點用「30 秒後 / 90 秒後」按鈕設，正式版才手填。
- **可見條件**：原型只分「開放 / 只有自己」。傳送過去看規則和難題時，只顯示開放的；融合、階段只有參與者看得到，來訪者只看到「只有參與者看得到」。
- **外觀資料**：`objects[].parts[]` 每個形體是 `{shape, size, color, offset}`，`look` 記預設外觀的名字（屋、碑、台、殿、工坊、樹、井、噴泉、山、塔），改外觀就是換一組 parts。走法表記的是 `objects[].id`，所以改外觀、搬位置代號都有效（測試有驗）。
- **單機兩個角色**：J1 是自己、J2 阿澄是預設的別人，兩個世界都在本機資料裡，表世界可以改兩邊的功能點。多人版才會把對方的世界從對方那裡讀進來。
- **鏡頭與操作**：點地面走路、點物件走到它旁邊；單指拖曳繞著角色轉鏡頭、兩指縮放（桌機用滾輪）。走路會沿著物件邊緣滑過去，不會穿過任何形體；點到物件裡面的點會自動推到邊上。
- **看得懂的提示**：每個物件頭上有名稱標籤（靠近才顯示功能）；繞圈時地上畫進度弧；傳送時畫面閃白。HUD 直接用自己的走法表算出「要去 J2：繞規則屋一圈，走到難題碑，再走到融合殿」，走過的段落劃掉；走法表湊不出來就提示去改表。
- **世界只能是資料，程式真的檢查**：任何世界（別人的、存檔裡的）讀進來之前都先過 `DATA.cleanWorld`：只抄已知欄位、檢查每個欄位的型別和格式（顏色只能 `#rrggbb`、形體只能四種、走法只能指到存在的物件、數量有上限），不合格就不載入並說明原因。函式、事件屬性這類東西根本抄不過來。
- **代號**：走法表的數字 0–9 都能設；沒有字母的 11 位數代號直接走 11 個數字（0 不能開頭）。
- **我是誰**：角色表可以切換「我是」哪個角色，走法表、裡世界都跟著換，重新整理也記得。單機測流程就是：當 J2 設好 J1 的出發點，走去 J1 的終點等。
- **自己的出發點**：那一微秒過了、沒人到終點，難題標為擱置並留紀錄；出發點標「已過」。重設出發點就是重創難題（狀態回到進行中）。相遇時雙方的難題都標為融合。
- **融合流程（v5 第二輪）**：規則全部在 `fusion.js`，純函式、node 可測；畫面在表世界的「融合」「點數紀錄」兩節，裡世界靠近融合殿／工坊會顯示摘要和「打開融合」。動作都以「我是」的角色做，單機就是切換角色輪流按。
  - 相遇那一微秒建立融合，雙方難題標「融合」。下一個出發點由一人提議、全員同意才算約好，約好後所有參與者的 `departUs` 都寫成同一微秒；期限到了由 `deadline()` 判：已可處理→完成；有非參與者在任一參與者的終點→加入、清掉期限要再約；只有參與者自己在終點或沒人→融合和原難題一起擱置。
  - 沒約好下一個出發點時，`proposeStage`／`claimStage`／`submitStage` 都會擋「先約下一個出發點」，畫面上階段區只顯示這句提示和「退出」。
  - 階段狀態：等同意 → 沒人負責 → 執行中 → 判定中 → 完成，另有「爭議」。全員同意的那一刻發題點（其他人各一份給構思者）；判定完成時發戰點（其他人各一份給執行者）。判定至少兩人，有人判未完成就爭議，爭議全員同意才能改判完成或退回執行中。
  - 退出：執行中／判定中／爭議中的階段變回沒人負責、不發戰點；已發的點數留著；退出者的難題標「退出」，跟擱置分開。
  - 點數的 `ruleVersion` 是發出者當下的規則版本號；每筆 1 點；簽章欄位先留空。
  - 角色表多了第三個預設角色 J3 小樂，用來測第三人加入。
- **表世界（v5 第三輪）**：改成活頁簿，`sheets.js` 用 `SHEETS` 設定每頁的表格（欄位、列 id、新增列、連結目標），通用表格畫欄字母、列號、凍結首欄；`SHEET.navigate(sheet, rowId)` 跳轉並閃那一列，`back()` 返回。資料格式：`role.problems[]` 有 `id/status/createdUs/prev`；`role.ruleVersions[]` 每版有 `no/atUs/items/ratios/resources`，`role.rules` 是目前版本的條目（給裡世界靠近顯示用）。
- **兌換（v5 第四輪）**：規則在 `exchange.js`。點數綁定發出者，只能向發出者換；每一點值多少大卡看那一點記下的 `ruleVersion` 在發出者規則裡的比例；換能量用最舊的點先；換資源用最舊的點補到夠，多的不找零；每筆兌換記在 `state.exchanges`，用掉的點標 `spent`。每日額度：發出者當天（本機日期）已發出的大卡加這筆不能超過 1800。
- **可見條件**：`DATA.canSee(state, owner, viewer, visible)`，三種值 `all / fused / self`；規則條目、難題、門都用它。裡世界靠近難題、規則、門時照這個判；表世界的規則頁和難題頁看別人的也照這個遮。
- **內部空間**：`WORLD.enter(id)`／`WORLD.leave()` 換場景，最多 3 層；內部畫一塊地板和四面矮牆。`cleanWorld` 遞迴洗內部物件，超過 3 層或代號重複就不載入。
- **還沒做**：簽章、多人連線（現在三個角色都在本機）、資源兌現後的實際交付（現在只留紀錄）。
