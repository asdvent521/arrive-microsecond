# 到達那微秒：平台核心設計

整理日期：2026-10-09。這份是平台核心的定案。原本的難題融合拆解設計改成東恆的村規，見 [VILLAGE-donghen.md](VILLAGE-donghen.md)。

2026-10-09 改版：一人一個角色，拿掉週期、空窗、結束並重創；每天的點數、規則表、資源表都是隔天生效；點不能轉手，收點時就選好要換的東西，貨當場留起來。

2026-10-10 補：改規則不溯及既往。已經成立的預約，照預約當時雙方的規則判；接受村規要記下接受的是哪一版。

2026-10-10 補（二）：以東西為主體，一換一。價格可以是 0：只給不收拿自己的試用品，只收不給拿自己建的空物件。

2026-10-10 補（三）：新手教學，跟引路人空的換空的（見 7-4）。

## 一句話

每個人每天發自己的點，規則公開透明；在約好的那一微秒相遇，規則有一方通就對接，一換一互換對方的東西，點數就是東西的價錢。

## 底層邏輯（不管系統怎麼演變，都不能走歪）

- **人需要能量才能活，這是鐵律。**
- 別人如果有能力創造我用得到的能量，我把一天的全部能量拿去換，就是**投資**；超出這一天，就是**冒險**。
- 系統的每一條規則都要能回到這一點來解釋：點數代表的是一個人一天的能量，不是錢。

## 平台和村規的分界

- **平台核心**只管：角色、每天的點、規則表、資源表、對接、點數帳，以及看得見規則的 3D 世界。
- **村規**：每個人寫在自己規則表裡的特殊規則。別人接受才跟你對接。村規要怎麼運作，由各人另外做系統處理，平台不管。
  - 例：題點、戰點、難題、融合、階段、熱量、判定，都是東恆的村規。

## 1. 角色

- 進系統先創角色。**一個人只有一個角色**：點數代表一個人一天的能量，一個人有很多角色，就等於一天發好幾份點。想分開的東西（例如工作和興趣）寫在同一張資源表。
- **每天的能量點**是角色最重要的屬性：預設每天 2000 點，玩家可以自訂成任何數字（10000、1 億都行）。
- **點以角色命名，不能轉手**：角色 A 發的叫 A點。拿到的 A點只能回 A 那裡換，不能拿去付給別人，所以 A 的點不會落到 A 不想往來的人手上。
- **A點對 A 自己沒用**：A點是給別人的。拿著 A點，就能找 A 換收點時選好的東西，所以 A 每天的點，就是 A 每天願意給別人的能力。
- 點數多少不需要系統限制：每天的點設多少都行，但給點一定要有貨撐著（見第 3 節），沒貨就給不出去，真正的上限是貨。
- **當天沒給出去的點，隔天歸零**：一個人的精力存不起來。

## 2. 每天一版（取代生命週期）

- **今天的角色整天不變**：每天的點數、規則表、資源表（種類、定義、價格、保留天數），今天改的都**隔天生效**，跟每天的點同一個換日時間。剛創的角色當下就生效。
- 明天起的改動今天就公開，大家看得到明天會變成什麼。
- 資源的數量不在此限，隨時可以加減（見第 3 節）。
- **每天就是一個版本**：對接紀錄記下判定用的那一版規則表和當天的資源表，所以紀錄本身就說明了雙方接受的是哪一套規則。
- **已經收下的點不受改版影響**：收點時選好的東西和價錢，照收的時候算。
- **改規則不溯及既往**：已經成立的預約，那一微秒照預約當時雙方的規則表判（對接條件、兩個開關、村規）；兩個來預約的人之間，照比較晚預約的那個人預約的時候。可換的貨、對接過幾次這些事實，還是照那一微秒當下算。之後的改版只管新的預約。
- **不玩了**：要先讓手上有你點的人換完，或取得他們同意，才能刪掉角色。
- 原本的週期（開始、結束）、點數到期作廢、結束並重創都拿掉了。

## 3. 收點就選好東西（取代空窗期）

- **收點的當下就選好要換什麼，之後不能改**：B 收 A點時，從 A 的資源表選要換的東西；收多少點，就是選的東西價錢加起來，不留零頭。還不確定要換什麼，就不該拿點。
- **貨當場留起來**：B 選的那份貨，平台當場替 B 留著，A 不能再給別人。A 的貨不夠，這筆點就給不出去，所以手上的點永遠有貨撐著，不會擠兌。
- **數量分兩種**：資源表每樣東西分「可換」和「已保留」。補貨、減貨只動可換的；已保留的，A 不能減。別人看到的是可換的數量。
- **保留多久由 A 決定**：A 在資源表每樣東西寫「保留幾天」；沒寫就一直保留到 B 換走。到期還沒換，點作廢，那份貨回到可換。收點時就看得到保留到哪天，帳房也寫著。
- **價格可以是 0**：0 點的東西不花每天的點，但一樣要有貨、一樣當場留起來。常見兩種：
  - **試用品**：想只給不收時拿出來的，例如「試聽 5 分鐘」。
  - **空物件**：想只收不給時拿出來的，名字和內容自己定，例如「空的：什麼都不給」。空物件要每個人自己建、自己補貨，平台不替人建；還沒建的人，平台會提醒。
- **想更彈性，交給村規**：例如村規寫「選了 X 想改成 Y，來找我」；平台上照樣記 X 換走了，實際給什麼是雙方的約定。
- 原本的空窗期拿掉了：空窗是缺貨時用的，現在沒貨就給不出點，不會缺貨。

## 4. 規則表與資源表

- **全部公開、透明、可查詢。**
- 規則表包含：
  - **我的點能做什麼**（例如 1 A點 = 陪跑 1 分鐘）。
  - **對接條件**：用固定格式寫，系統才能自動判斷通不通，沒有模糊空間（見下）。
  - **村規**：自由文字，給人看。**誰寫的村規就由誰解釋**，不另設解釋權欄位。
- 資源表：我的點能換的具體東西，每樣寫名字、定義、價格（要幾 A點，可以是 0）、保留幾天（可以不寫），數量分可換和已保留（見第 3 節）。種類、定義、價格、保留天數改了都隔天生效（見第 2 節）。

### 對接條件的格式

每一條是「欄位、比較、數值」，例如：

| 欄位 | 例 |
|---|---|
| 對方可換的貨（全部加起來） | ≥ 5 份 |
| 對方手上有多少我的點 | ≥ 0 |
| 對方對接過幾次 | ≥ 3 |

原本的「對方每天的點數」拿掉了：每天的點數自己設多少都行，看不出什麼。「對方週期還剩多久」「對方狀態」跟著週期、空窗一起拿掉。

另外有兩個開關：

- **要求兩方都通**（預設關）。
- **對方一定要接受我的村規，才有對接的基本資格**（預設關）。這是平台對村規唯一的處理：只記「接受了沒、接受的是哪一版」，村規的內容和執行平台都不管。村規改了，舊的接受就不算數，要重新接受；已經成立的預約照預約時那一版（見第 2 節）。

欄位清單之後可以再加，但每一個都必須是系統查得到的事實。

### 村規驗證碼（選用）

- 規則表可以加一條條件：**對方要持有我的村規網站發的驗證碼**。
- 村規網站（各人自己架的村規系統）審核過對方，就發一組驗證碼給他；平台只用村規網站公布的公開金鑰檢查這組碼是不是真的，不需要知道村規內容。
- 這讓「對方一定要接受我的村規」可以被驗證，而不是只靠勾選。不想這麼嚴格的人可以不用。

## 5. 對接

1. **查詢**：規則表全部公開、對接條件是固定格式，所以系統直接算出：
   - **我符合誰的條件**（我可以去找的人）、**誰符合我的條件**（可能來找我的人）。兩張合起來就是「一方通」的所有人。
   - **查資源**：用關鍵字查誰的點能換到我要的東西。
   - **輸入代號**：直接看某個角色的規則；或在 3D 世界走出他的代號過去看。
   - 排序只照事實（最近的對接時段、每天的點數、對接過幾次），平台不評好壞。
2. **預約對接時段**：對接一定要在約好的**那一微秒**。
   - 主人在終點公開幾個**對接時段**（精確到微秒），每個時段設**名額**。
   - 想對接的人**一定要預約**，而且條件要通才能預約；約滿就不能再約。條件不通的人根本約不了，主人不用看。
   - 名額是容量，不是條件。
3. **找到對方**：在自己的世界走出對方的代號，開白光傳送門過去，沿路看對方的規則建築，走到終點。
4. **那一微秒判定**：
   - **雙方規則表只要有一方通，就能對接。**
   - 任一方的規則表打開「要求兩方都通」，就要兩方都通。
   - 任一方打開「對方一定要接受我的村規」，對方沒接受就沒有對接資格。
   - 同一個時段在場的不只兩個人時，任兩個人之間各自照上面判定，例如 A 和 C 一起跟 B 換。
   - 判定用的是預約當時雙方的規則表（見第 2 節「改規則不溯及既往」），事實照那一微秒算。
5. **互換東西（一換一）**：
   - 那一微秒之前，每個人先選好要換別人的什麼（預約後到那一微秒之前都能選、能改），也設好「每人最多給多少點」。
   - **一換一**：同一對之間，兩邊都選了對方的東西才成交；只有一邊選，這一對就不成交，照事實記錄。只給不收：拿出自己 0 點的試用品，並選對方的空物件；只收不給：讓對方選自己的空物件（見第 3 節）。
   - 那一微秒，平台照選好的成交：兩邊都要給得出——對方選的價錢加起來不超過我的上限，我當天還剩的點和可換的貨也夠——才成交，點給出去、貨當場留起來（見第 3 節）；任一邊給不出，整對都不成交，照事實記錄。成交的當下就定了，之後不能改。
   - **平台禁止預支**：今天的點只能今天給，不能先給明天以後的點。不能存（隔天歸零）、也不能借，點數永遠只代表「今天這個人」，平台裡永遠沒有欠款。
6. **留紀錄**：對接紀錄記下雙方角色、時間、各給了多少點、各選了什麼，以及判定用的那一版規則表和當天的資源表（見第 2 節）。
   - 角色碑顯示最近幾次對接的**換點比例**（給出的點：收到的點），從公開的對接紀錄算，平台不評好壞。

### 聯絡

- 平台不做文字訊息功能。
- **聯絡方式欄**：主人自己填（電話、LINE ID、Email，或不填）。**只有預約成功的人看得到**；對接結束或角色刪掉後自動隱藏。要不要暴露真實身分由每個人自己決定。

## 6. 點數帳與兌現

- 點數帳：誰手上有誰的點、多少、從哪一次對接拿到的、選了什麼、保留到哪天。
- **兌現**：拿著 A點到 A 的市集，換收點時選好的那樣東西；貨已經留著，一定換得到。保留天數到了還沒換，點作廢，貨回到可換。
- 每筆點數保留簽章欄位，多人版由發出者簽章，沒人能冒用別人發點。

## 村規怎麼運作

- **平台只做三件事：記事實、全部公開、不替任何人執行承諾。**
- 村規是建立在這些公開事實上的約定。例：A 的村規寫「我願意預支，承諾給你 5000 點，分三天給」，平台看到的只是三次普通對接（每次都不超過當天的點）；三次合起來是在履行承諾，這件事由村規和信用處理，平台不管。違約的代價是大家都查得到的紀錄，不是平台處罰。
- 所以冒險可以存在，但它是人對人的承諾，不是平台裡的點數。
- **村規系統是另外的程式，只讀平台的公開資料**（對接紀錄、規則表、資源表、點數帳的公開部分），用來算自己的東西（例如東恆村規的題點、戰點、難題、融合），記在自己的帳上。
- **村規系統只能讀、不能寫**：不能替平台產生點數，也不能突破每天的上限。這是底層邏輯的保險。
- 平台要做到的只有：資料公開、格式固定、查得到。

## 7. 兩種介面，同一套功能

**一份資料、兩種介面。**規則層（`core.js`）只有一套，裡世界和表世界都只呼叫它。**每一個動作在兩邊都做得到**，差別只在怎麼做：裡世界像遊戲，表世界是簡單的 Excel 表。隨時可以切換，切換時盡量停在同一件事上（例如在裡世界站在 J2 的規則屋，切到表世界就是 J2 的規則表）。

### 7-1. 裡世界：像遊戲

裡世界存在的理由：**走進一個人的世界，看得見他的規則建築，就能瞭解他的規則。**

- **畫面幾乎全給 3D**，沒有表格、沒有分頁列。只留：
  - 左上：角色名牌，加一條**能量條**（今天還能給多少點）。底層邏輯就是能量，給點時能量條往下降。
  - 右上：切換到表世界的按鈕；那一微秒快到時才出現倒數。
  - **任務提示**（取代「下一步」頁）：一行字，例如「下一步：開對接時段 → 走到終點台」。
- **互動用遊戲的方式**：點建築就走過去；到了從底部升起對話框，給幾個選項按鈕（像 RPG 的選項），不蓋住建築。
- **指引**：要去某個代號時，地上亮出一串光點，照著走就走得出代號，不用讀長句子。
- **建造模式**：在自己的世界長按物件，可以搬移、換外觀、換顏色、加門、設定走法。
- **對接那一微秒**：倒數、白光、在場的人相遇。倒數時升起「交換」對話框：選要換每個人的什麼、看別人要我的什麼（一換一，兩邊都選了才成交）、設每人最多給多少點（上限是能量條剩下的）；那一微秒照選好的成交，能量條往下降。
- 角色序號、走代號、白光傳送門、功能點外觀自由、內部空間、世界只能是資料：沿用 v5、v6 的做法。

平台的功能點（功能固定，外觀自由）：

| 功能 | 在裡世界做什麼 | 預設外觀 |
|---|---|---|
| 規則 | 閱讀規則（像翻一本書）、接受村規；自己的：改規則（隔天生效） | 屋 |
| 資源 | 像商店：看價錢、可換的數量、保留幾天，兌現自己選好的東西；自己的：上架、改價錢和保留天數（隔天生效）、補貨和減貨（馬上） | 市集 |
| 終點 | 像時刻表：看時段、預約、先選要換主人的什麼；自己的：開時段、看預約、先選要換預約者的什麼；那一微秒站在這裡對接 | 台 |
| 角色 | 看每天的點、換點比例、明天起的改動；自己的：改每天的點（隔天生效）、不玩了、歷史紀錄 | 碑 |
| 點數 | 像背包：手上有誰的點、選了什麼、保留到哪天；只有自己看得到 | 帳房 |
| 地標 | 沒有功能，用來走代號 | 自由 |

- 規則、資源、終點、角色**一律公開**；點數帳只有自己看得到。
- **查詢**在裡世界是一張「地圖」：一方通的角色亮著，其他暗著；點一個人就顯示怎麼走過去。
- 村規想表現成建築，可以用地標加內部空間自己蓋，平台只負責顯示。

### 7-2. 表世界：簡單的 Excel 表

- **沒有 3D、沒有遊戲介面**，只有表。
- **一張工作表只放一張表**。下方是工作表分頁，用 Excel 的分頁顏色分組：待辦（第一頁）、我的（藍）、找人（綠）、帳本（金）。
- 表頭是欄位名稱，左邊列號，第一欄凍結；不放欄字母、不放 fx 編輯列、不放大段說明（說明集中在最後一頁「說明」）。
- 按鈕放在格子裡；代號、功能點、時段都可以點，跳到對應那一列。
- **表世界不用走路**：看別人的規則直接點代號；對接時在「我預約的」那一列勾「到場」，等於站在終點上，那一微秒照樣判定；要換的東西和每人最多給多少點也在同一列選。

### 7-3. 功能對照（兩邊都要做得到）

| 功能 | 裡世界 | 表世界 |
|---|---|---|
| 下一步 | 任務提示 | 待辦 |
| 改每天的點（隔天生效）、不玩了；單機版換人（測試用） | 角色碑 | 角色 |
| 改規則（隔天生效）、看別人的規則、接受村規 | 規則屋 | 規則用途、對接條件、開關與村規 |

| 去對方那裡 | 走代號、傳送門 | 點代號 |

### 7-4. 新手教學：空的換空的

- 第一次打開就是新手教學。玩家跟「引路人」用空物件換空物件，雙方都不損失，把整套流程走一遍。
- **只有一份步驟**：在哪個世界，提示就講那個世界的做法；兩個世界各自都能走完，中途切換就從同一步接著走。
  1. **創角色**：取名字、每天的點（預設 2000），建第一樣東西「空的」（0 點，補 1 份）。創角色當下就生效，所以空物件在這一步建。
  2. **找引路人**：裡世界打開地圖，照光點走出他的代號、進傳送門；表世界在「我可以去找」點他的代號。
  3. **預約、選他的「空的」**：引路人一定會選你的「空的」。
  4. **那一微秒**：裡世界站在他的終點台上，表世界勾「到場」。成交後寫「我拿出：空的；拿到：引路人的空的」。
  5. **看拿到什麼**：裡世界看帳房，表世界看「點數」。
  6. **兌現**：裡世界到引路人的市集，表世界到「兌現」，把它換掉。
- **走完問：要不要用另一種介面再走一次？**
  - 要：切到另一個世界，從「補 1 份空的」開始，用同一套步驟再跟引路人換一次。
  - 不要：切到另一個世界帶看對照，一步一步指出剛才那筆交換在這邊的哪裡（例如帳房＝點數），看完切回原來的世界。
- **引路人**：平台的教學角色，有自己的世界、「空的」和時段。玩家走到預約那一步才開時段，大約一分鐘後；他一定到場。
- **教學的對接不算數**：不算進「對接過幾次」和換點比例，對接紀錄標「教學」。
- **可以跳過**：跳過的話只做第 1 步（創角色），其他略過；空物件的提醒照樣會出現。
- 示範版不再預先放好「我」，第一次打開就從創角色開始。

## 8. 資料存放（三層，玩家自己選）

| 方式 | 玩家要做什麼 | 適合誰 |
|---|---|---|
| **平台代管（預設）** | 什麼都不用做，註冊就能玩 | 大部分人 |
| **存到自己的雲端硬碟** | 第一次授權，之後自動存 | 在乎資料在自己手上的人 |
| **自己架** | 放到自己的網站空間 | 會技術、想完全掌控的人 |

- 3D 世界、規則表、資源表本來就公開，放平台沒有隱私問題；一個世界只是幾 KB 的資料。
- **敏感資料（例如聯絡方式）端對端加密**：平台只幫忙傳，自己讀不到；只有預約成功的人能解開。
- 資料格式公開，想自己存、自己架的人隨時能搬走，不被平台綁住。
- 不管存在哪裡，**世界只能是資料，不能是程式**：讀別人的世界只讀資料，畫面由自己的程式畫。

> 下面 v6、v7 的實作備註記的是當時的做法。2026-10-09 改版後，跟第 1～7 節衝突的（週期、空窗、草稿、拒絕、交換滑桿等）以第 1～7 節為準；v8 照 [PLAN-v8.md](PLAN-v8.md) 做。

## v6 實作備註

照上面的定案做在 `v6/`（見 [PLAN-v6.md](PLAN-v6.md)）。實作上補的決定：

- **主人那一方給多少**：單機版主人不在場，所以開對接時段時就填「每次給多少點」，對接那一微秒以當天剩下的為上限自動扣；來的人站在終點上時自己填要給多少。
- **提早結束的同意**：單機版持有人都在本機，「結束並重創」視為持有人都同意；多人版要真的收同意。
- **聯絡方式**：預約成功、還沒對接完的那個時段期間看得到；對接完或主人結束就隱藏。
- **草稿**：建角色先開草稿（名字、每天的點、週期、規則、資源、聯絡方式），按「創角色」才寫進角色表並算 `rulesHash`；之後規則頁只有「結束並重創」，重創的草稿帶著原規則和前身。
- **兌現失敗自動空窗**：規則函式丟出錯誤前已經把角色改成空窗、記下欠的那一筆；表世界失敗時也存檔重畫，所以紀錄立刻公開。
- **空窗角色的拒絕**：`canRefuse(owner, visitor)` 只在「主人在空窗、而且主人不通預約者的條件（做不到對方的要求）」時成立；其他情況一律不能拒絕（不在空窗的主人靠規則表的條件擋人，不能手動拒絕）。對接時段頁只在這種情況才出現「拒絕（做不到對方的要求）」按鈕；拒絕後預約拿掉、留公開紀錄。
- **規則層也守那一微秒**：`dock()` 只接受時段那一微秒的判定：`atUs` 要在 `[slot.atUs, slot.atUs + 1 秒)` 內（畫面層每 50 毫秒判一次，那一微秒的結果在下一格送進來）；超過就標為錯過、丟錯誤，之後這個時段不能再對接。`expire()` 每格清算：過了判定窗還沒對接的預約全部標為錯過，留紀錄。
- **功能點 id**：預設世界的物件 id 帶序號（例如 `rule_00000000001`），避免不同角色的世界互相撞名。
- **Three.js 直接打包**：r128 的 `three.min.js`（MIT）放在 `v6/src/vendor/`，組進單一 HTML，手機不用連 CDN；引擎真的沒載入時 `WORLD` 換成什麼都不做的替身，裡世界顯示「3D 引擎沒載入」，表世界照常。
- 門的可見條件只有「所有人／只有自己」（沒有「融合過的人」，那是村規的概念）。

## v7 實作備註

照第 7 節做在 `v7/`（見 [PLAN-v7.md](PLAN-v7.md)）。`core.js` 原封不動，只在最後面加一段；實作上補的決定：

- **規則層只加不改**：加了 `presence`（表世界「到場」的狀態，`setPresent`／`isPresent`）、`myBookings`（我預約的、還沒判定的時段）、`judge`（那一微秒的判定：站在終點上或勾了到場都算到場，各自要給多少點一起送進 `dock`）。到場狀態用完就清掉，不留在存檔裡。
- **判定在接線層每格做一次**：`app.js` 每 50 毫秒呼叫 `judge` 與 `expire`，裡世界（站在終點上）和表世界（勾到場）只是把「到場」告訴 `app.js`，不各自寫帳。
- **任務提示與待辦共用**：`app.js` 的 `steps()` 算六步與下一步，裡世界顯示一行「下一步：⋯ → 走到⋯」，表世界整張待辦表。
- **切換停在同一件事上**：`app.js` 記「哪個角色、哪個功能」。裡世界靠近哪個建築就記那個功能；表世界看誰、看哪張表就記那個角色與功能。切過去時裡世界走到對應建築旁、表世界開對應工作表並把「看誰」設成那個角色。
- **建造模式的走法**：改外觀、換顏色、搬移、加門都不碰走法表，所以走法照樣有效；刪物件才連帶刪用到它的走法。
- **交換滑桿**：預約了、站在對方終點上、距那一微秒不到 60 秒就升起，拉多少就記多少；沒拉預設 100 點，一樣以當天剩下的為上限。
- **擋掉 Three.js**：裡世界只顯示「3D 引擎沒載入」，切換鈕照常，表世界完整可用。
- **「走到」停下來才算，路過不算**：到達只有兩種情況：(a) 點了這棟建築、走到它旁邊停下；(b) 點地面、停下來的位置在這棟建築的範圍內。還在走、要去別的地方時經過它的範圍不算到達，所以從角色碑直線走到市集擦過終點台也不會被算成走到終點台。繞圈的判定不變。
- **對話框只在停下來時打開**：靠近、路過都不開，跟「走到」一致；開始走路就收起。
- **走代號時不自動升對話框**：正在走代號（已經走出字母或數字）或地上有指引光點時，到達建築只在上方跳一行小字「到了角色碑」，附「看看」（打開對話框）和「繞一圈」（走法表有用到這棟時）；不升起對話框、不擋住下一棟。沒在走代號時，停在建築旁照舊自動打開對話框。
- **先繞出字母才算開始走代號**：裡世界只有在已經繞出字母、或地圖指引開著時，走到建築才算輸入數字；沒有字母也沒有指引時，在建築之間走來走去不算，停下就照常打開對話框。（規則層的解碼器本身仍接受純數字的 11 位序號；要走 11 位序號就先用地圖開指引。）
- **繞完一圈的那棟就算人在那裡**：下一段「走到」從這棟算起（走法表設「規則屋→市集＝2」，繞完規則屋直接走到市集就是 2，不用先走到規則屋）。地圖指引的光點和路線說明也從這棟算起。規則層只加：`Decoder.feedV7`、`routeV7`，原本的 `feed`、`route` 不動。
- **表世界蓋著時 3D 暫停**：切到表世界就不畫、不跑走路；切回裡世界從原地繼續。
- **代號行的 ✕**：有走到一半的代號或地上光點時，名牌下的代號行有一個小 ✕，按了把代號、繞圈、光點、傳送門一起清掉，之後停在建築旁照常開對話框。
- **傳送門看得到**：白光之外加一圈銅色外框和地上的光暈，上面有名牌「傳送門 → 阿澄（J2）」；上方提示有「進去」，點門或按「進去」都進得去。
- **切換時「沒換看別的東西」就一切照舊**：切到表世界再切回，走到一半繼續走去原本點的地方，光點和代號都留著，切走前開著的對話框也照樣開著，而且用最新的資料重畫（在表世界補了貨，切回來補貨對話框的數量是新的）。「換看了別的東西」是比對焦點（哪個角色、哪個功能）真的有沒有變，再點一次同一張工作表不算。只有換看了別的東西（例如點數），切回來才走去那棟。走路途中切過去，表世界開的是「要去的那棟」對應的工作表。
- **吐司放在對話框上面**：對話框開著時吐司往上移到對話框頂上，不蓋住按鈕。
- **上方提示留到走開為止**：提示的字那一塊讓手指點穿過去（點到字等於點到後面的 3D），只有「看看」「繞一圈」「進去」接得到。傳送門的提示一直留著，直到進門或按 ✕。
- **暫停時取消已排好的下一格**：避免同一格內切過去又切回疊出兩個畫面迴圈。
- **繞一圈**：站在建築旁時，自己的走法表有用到這棟建築的繞圈，對話框（或上方提示）就有「繞一圈（J）」按鈕，按了自動繞一圈。繞完一圈當下就走出字母、進入走代號狀態，不等離開範圍。手動點地面繞也繞得成：站在旁邊點到建築本身時，改走到建築背後的地面，不會卡住。

## v8 實作備註

照 2026-10-09 改版後的第 1～7 節做在 `v8/`（見 [PLAN-v8.md](PLAN-v8.md)）。規則層 `core.js` 這一版重寫；介面沿用 v7 的手感。實作上補的決定：

- **版本怎麼存**：角色有一串 `versions`，每個版本記「從哪一天起」（本機日期，用天數比大小）、每天的點、規則表、資源表（種類、定義、價格、保留天數）。今天生效的是最後一個「從哪一天起 ≤ 今天」的版本；明天起的最多一個，改了就改它，沒有就從今天的複製一份。沒改過的日子共用同一個版本，所以「每天的版本都留著」是留每個有改的版本；對接紀錄記雙方那天版本的編號。
- **數量不在版本裡**：每樣資源的「可換」「已保留」記在角色的 `stock`，隨時加減；明天起才上架的東西今天就能先補貨。
- **保留（點數帳）的資料**：一筆保留記發點的人、持有人、東西、收的時候的價錢、哪次對接、保留到哪天（空白＝一直）、狀態（保留中／換了／到期作廢／作廢）。「對方手上有多少我的點」＝他保留中的我的東西價錢加起來；「今天給出去的點」＝今天成立的保留價錢加起來。
- **那一微秒的判定做一次**：判定窗（那一微秒起 1 秒內）第一次看到就判，之後不再判；到場的人兩兩判定、成立的每一對兩個方向各自成交；沒到場的預約標錯過。程式沒開著錯過判定窗，預約的人全部算錯過。單機版主人視為到場。
- **「每人最多給」沒設就是當天剩下的**：超過自己設的上限記「每人最多給 N 點」，超過當天剩的記「不能預支」。
- **一換一怎麼做**：條件通的每一對，兩邊都選了對方的東西（扣掉那天已下架的還有剩）、兩邊都給得出（每人上限、當天剩的點、貨夠），整對才成交；只有一邊選或任一邊給不出，整對不成交，兩邊都不給點、貨都不動，對接紀錄的 `traded` 記 false、`reason` 寫原因（「一換一：阿澄 沒選 我 的東西」「甲 的貨不夠：…，整對不成交」）。「對接過幾次」和換點比例只算成交的。價格可以是 0：0 點的東西不扣每天的點，但一樣要有貨、一樣保留、一樣可以兌現和到期。空物件平台不替玩家建；待辦提醒沒建或可換 0 份；交換對話框和表世界的格子提醒「還沒選對方的東西：一換一，兩邊都選了才成交」。補貨可以直接輸入數量。示範資料阿澄多一樣 0 點的試用品「試聽 5 分鐘」。單機版主人不在場，主人要的東西要「換人」成主人去選，待辦寫了這一步。
- **不玩了**：刪掉角色時，別人保留中的我的東西作廢（持有人同意），我保留中的別人的東西也作廢、貨回到他的可換；預約一併取消。單機版刪掉自己就換成第一個還在的人；全部刪光就回到初始資料。
- **示範資料**：J2 的條件改成「對方可換的貨 ≥ 5 份」（舊的「對接過幾次」會讓一開始誰都約不了 J2）；J3 要求兩方都通、接受村規。預設每天 2000 點，示範角色自訂成 1800、2000、800。
- **交換對話框的開法**：站在對方終點上、距那一微秒不到 60 秒就升起，蓋過其他對話框（時刻表開著也一樣）；只有正在「我要他的什麼」選東西時，等存好或關掉再升起。
- **選的東西那天已經下架**：跟畫面一致，下架的那幾樣不算，剩下的照原本的規則成交（上限、當天剩的點、貨夠不夠照舊）；全部都下架這個方向就是 0 點。對接紀錄和結果對話框寫「選的「X」那天已經下架，沒換到」；選東西的畫面、交換對話框、表世界的「我要的」「他要我的」存著的選擇裡有被拿掉的，加一行小字「選的「X」那天已經下架，不算」。不出錯；那一微秒每一對各自判，一對出錯不影響其他對，出錯也留紀錄；選東西的畫面和存選擇時自動拿掉那天已經不在資源表上的東西。
- **「對方可換的貨」只算那個時間生效的版本裡有的東西**：明天起才上架的、已經下架的不算。
- **改規則不溯及既往怎麼做**：預約時記下那一刻（`bookedAt`）。那一微秒每一對：主人和預約的人之間用預約那一刻雙方生效的版本，兩個預約的人之間用比較晚預約的那一刻；條件表、兩個開關、村規都從那一版拿，條件裡的事實（可換的貨、手上有多少我的點、對接過幾次）照那一微秒算。對接紀錄記 `ruleUs` 和判定用的 `verA`／`verB`。
- **接受村規記版本**：`acceptances` 記接受時那一版的村規內容；判定時接受的要是判定用那一版的村規才算，村規改了舊的接受不算。畫面：接受的是舊版寫「你接受的是舊版村規，要重新接受」、按鈕照樣出現；明天起村規有改寫「明天起村規改了，到時候要重新接受」。
