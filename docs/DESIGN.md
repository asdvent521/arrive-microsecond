# 到達那微秒：平台核心設計

整理日期：2026-10-07。這份是平台核心的定案。原本的難題融合拆解設計改成東恆的村規，見 [VILLAGE-donghen.md](VILLAGE-donghen.md)。

## 一句話

每個角色每天發自己的點，規則公開透明；在約好的那一微秒相遇，規則有一方通就對接，互相拿對方的點。

## 底層邏輯（不管系統怎麼演變，都不能走歪）

- **人需要能量才能活，這是鐵律。**
- 別人如果有能力創造我用得到的能量，我把一天的全部能量拿去換，就是**投資**；超出這一天，就是**冒險**。
- 系統的每一條規則都要能回到這一點來解釋：點數代表的是一個人一天的能量，不是錢。

## 平台和村規的分界

- **平台核心**只管：角色、每天的點、規則表、資源表、對接、點數帳，以及看得見規則的 3D 世界。
- **村規**：每個人寫在自己規則表裡的特殊規則。別人接受才跟你對接。村規要怎麼運作，由各人另外做系統處理，平台不管。
  - 例：題點、戰點、難題、融合、階段、熱量、判定，都是東恆的村規。

## 1. 角色

- 進系統先創角色。一個人可以有很多角色。
- **每天的能量點**是角色最重要的屬性：預設每天 1800 到 2000 點，玩家可以自訂成任何數字（10000、1 億都行）。
- **點以角色命名，彼此不互通**：角色 A 產生的叫 A點。A點和 B點預設不能互換，要雙方同意。
- **A點對 A 自己沒用**：A點是給別人的。拿著 A點，就能找 A 兌現他定義的東西，所以 A 每天的點，就是 A 每天願意給別人的能力。
- 點數多少不需要系統限制：A點能做什麼由 A 自己定義，發太多，每一點自然就不值錢。
- **當天沒給出去的點，隔天歸零**：一個人的精力存不起來。

## 2. 生命週期（取代規則版本表）

- 創角色時寫下**開始、結束兩個微秒**，長短由玩家決定。
- **週期內規則表一個字都不能改**。要改，就先結束這個角色，再創新角色。每個角色本身就是一個版本，跟你對接的人永遠知道自己接受的是哪一套規則。
- **點數到期作廢**：角色週期結束，他的點就失效。對接時大家都看得到結束時間，等於點數印好了到期日。
- **提早結束**：要先讓持有人兌現，或取得他們同意，才能結束。

## 3. 空窗期

- 資源暫時不夠、維持不了角色時，可以進入空窗期。
- 空窗期間角色變成「無」：
  - 每天的點停發；別人手上的點暫停兌現。
  - 週期時鐘照走，到期一樣結束。
  - **不能設任何條件擋別人來問能不能對接。唯一能拒絕的理由：做不到對方規則表的要求。**
- 空窗結束，回到原本的角色、原本的規則。

## 4. 規則表與資源表

- **全部公開、透明、可查詢。**
- 規則表包含：
  - **我的點能做什麼**（例如 1 A點 = 陪跑 1 分鐘）。
  - **對接條件**：用固定格式寫，系統才能自動判斷通不通，沒有模糊空間（見下）。
  - **村規**：自由文字，給人看。
- 資源表：我的點能兌現的具體東西和價格（要幾 A點）。資源的數量可以增減；種類和定義跟規則一樣，週期內固定。

### 對接條件的格式

每一條是「欄位、比較、數值」，例如：

| 欄位 | 例 |
|---|---|
| 對方每天的點數 | ≥ 1000 |
| 對方週期還剩多久 | ≥ 30 天 |
| 對方狀態 | 不是空窗 |
| 對方手上有多少我的點 | ≥ 0 |
| 對方對接過幾次 | ≥ 3 |

另外有一個開關：**要求兩方都通**（預設關）。欄位清單之後可以再加，但每一個都必須是系統查得到的事實。

## 5. 對接

1. **約時間**：對接一定要在約好的**那一微秒**。主人在自己的終點寫下對接時間（精確到微秒）。
2. **找到對方**：在自己的世界走出對方的代號，開白光傳送門過去，沿路看對方的規則建築，走到終點。
3. **那一微秒判定**：
   - **雙方規則表只要有一方通，就能對接。**
   - 任一方的規則表打開「要求兩方都通」，就要兩方都通。
   - 對方在空窗期：只能以「做不到對方規則表的要求」拒絕。
4. **互給點數**：對接成立後，A 拿到 B點，B 拿到 A點。給多少各自決定，但不能超過自己當天還剩的點。
5. **留紀錄**：對接紀錄記下雙方角色、時間、各給了多少點。角色就是版本，所以紀錄本身就說明了雙方接受的是哪一套規則。

## 6. 點數帳與兌現

- 點數帳：誰手上有誰的點、多少、從哪一次對接拿到的。
- **兌現**：拿著 A點，照 A 的資源表向 A 換東西。A 在空窗期時暫停兌現；A 的週期結束後，A點作廢。
- 每筆點數保留簽章欄位，多人版由發出者簽章，沒人能冒用別人發點。

## 7. 3D 裡世界（一定保留）

裡世界存在的理由：**走進一個人的世界，看得見他的規則建築，就能瞭解他的規則。**

- 角色序號、走代號、白光傳送門、功能點外觀自由、內部空間、世界只能是資料：沿用 v5 的做法，細節見 [VILLAGE-donghen.md](VILLAGE-donghen.md) 的對應章節。
- 平台的功能點：

| 功能 | 對應 | 預設外觀（可改） |
|---|---|---|
| 規則 | 規則表（我的點能做什麼、對接條件、村規） | 屋 |
| 資源 | 資源表、兌現 | 市集 |
| 終點 | 對接時間，對接在這裡發生 | 台 |
| 角色 | 每天的點、生命週期、狀態（活著／空窗） | 碑 |
| 點數 | 點數帳（只有自己看得到） | 帳房 |
| 地標 | 沒有功能，用來走代號 | 自由 |

- 規則、資源、終點、角色**一律公開**；點數帳只有自己看得到。
- 村規想在世界裡表現成建築，可以用地標加內部空間自己蓋，平台只負責顯示。

## 8. 表世界

活頁簿格式沿用 v5（一張表一頁、欄字母、列號、凍結首欄、連結跳轉）。頁面順序：

**下一步｜角色｜規則｜資源｜世界｜走法｜對接時間｜對接紀錄｜點數｜兌現**
