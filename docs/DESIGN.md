# 到達那微秒：平台核心設計

整理日期：2026-10-07。這份是平台核心的定案。原本的難題融合拆解設計改成東恆的村規，見 [VILLAGE-donghen.md](VILLAGE-donghen.md)。

## 一句話

每個角色每天發自己的點，規則公開透明；在約好的那一微秒相遇，規則有一方通就對接，互相拿對方的點。

## 底層邏輯（不管系統怎麼演變，都不能走歪）

- **人需要能量才能活，這是鐵律。**
- 別人如果有能力創造我用得到的能量，我把一天的全部能量拿去換，就是**投資**；超出這一天，就是**冒險**。
- 系統的每一條規則都要能回到這一點來解釋：點數代表的是一個人一天的能量，不是錢。

## 平台和村規的分界

- **平台核心**只管：角色、每天的點、規則表、資源表、對接、點數帳，以及看得見規則的 3D 世界。
- **村規**：每個人寫在自己規則表裡的特殊規則。別人接受才跟你對接。村規要怎麼運作，由各人另外做系統處理，平台不管。
  - 例：題點、戰點、難題、融合、階段、熱量、判定，都是東恆的村規。

## 1. 角色

- 進系統先創角色。一個人可以有很多角色。
- **每天的能量點**是角色最重要的屬性：預設每天 1800 到 2000 點，玩家可以自訂成任何數字（10000、1 億都行）。
- **點以角色命名，彼此不互通**：角色 A 產生的叫 A點。A點和 B點預設不能互換，要雙方同意。
- **A點對 A 自己沒用**：A點是給別人的。拿著 A點，就能找 A 兌現他定義的東西，所以 A 每天的點，就是 A 每天願意給別人的能力。
- 點數多少不需要系統限制：A點能做什麼由 A 自己定義，發太多，每一點自然就不值錢。
- **當天沒給出去的點，隔天歸零**：一個人的精力存不起來。

## 2. 生命週期（取代規則版本表）

- 創角色時寫下**開始、結束兩個微秒**，長短由玩家決定。
- **週期內規則表一個字都不能改**。要改，就先結束這個角色，再創新角色。每個角色本身就是一個版本，跟你對接的人永遠知道自己接受的是哪一套規則。
- **點數到期作廢**：角色週期結束，他的點就失效。對接時大家都看得到結束時間，等於點數印好了到期日。
- **提早結束**：要先讓持有人兌現，或取得他們同意，才能結束。

## 3. 空窗期

- 資源暫時不夠、維持不了角色時，可以進入空窗期。
- 空窗期間角色變成「無」：
  - 每天的點停發；別人手上的點暫停兌現。
  - 週期時鐘照走，到期一樣結束。
  - **不能設任何條件擋別人來問能不能對接。唯一能拒絕的理由：做不到對方規則表的要求。**
- 空窗結束，回到原本的角色、原本的規則。

## 4. 規則表與資源表

- **全部公開、透明、可查詢。**
- 規則表包含：
  - **我的點能做什麼**（例如 1 A點 = 陪跑 1 分鐘）。
  - **對接條件**：用固定格式寫，系統才能自動判斷通不通，沒有模糊空間（見下）。
  - **村規**：自由文字，給人看。**誰寫的村規就由誰解釋**，不另設解釋權欄位。
- 資源表：我的點能兌現的具體東西和價格（要幾 A點）。資源的數量可以增減；種類和定義跟規則一樣，週期內固定。

### 對接條件的格式

每一條是「欄位、比較、數值」，例如：

| 欄位 | 例 |
|---|---|
| 對方每天的點數 | ≥ 1000 |
| 對方週期還剩多久 | ≥ 30 天 |
| 對方狀態 | 不是空窗 |
| 對方手上有多少我的點 | ≥ 0 |
| 對方對接過幾次 | ≥ 3 |

另外有兩個開關：

- **要求兩方都通**（預設關）。
- **對方一定要接受我的村規，才有對接的基本資格**（預設關）。這是平台對村規唯一的處理：只記「接受了沒」，村規的內容和執行平台都不管。

欄位清單之後可以再加，但每一個都必須是系統查得到的事實。

### 村規驗證碼（選用）

- 規則表可以加一條條件：**對方要持有我的村規網站發的驗證碼**。
- 村規網站（各人自己架的村規系統）審核過對方，就發一組驗證碼給他；平台只用村規網站公布的公開金鑰檢查這組碼是不是真的，不需要知道村規內容。
- 這讓「對方一定要接受我的村規」可以被驗證，而不是只靠勾選。不想這麼嚴格的人可以不用。

## 5. 對接

1. **查詢**：規則表全部公開、對接條件是固定格式，所以系統直接算出：
   - **我符合誰的條件**（我可以去找的人）、**誰符合我的條件**（可能來找我的人）。兩張合起來就是「一方通」的所有人。
   - **查資源**：用關鍵字查誰的點能換到我要的東西。
   - **輸入代號**：直接看某個角色的規則；或在 3D 世界走出他的代號過去看。
   - 排序只照事實（最近的對接時段、每天的點數、對接過幾次），平台不評好壞。
2. **預約對接時段**：對接一定要在約好的**那一微秒**。
   - 主人在終點公開幾個**對接時段**（精確到微秒），每個時段設**名額**。
   - 想對接的人**一定要預約**，而且條件要通才能預約；約滿就不能再約。條件不通的人根本約不了，主人不用看。
   - 名額是容量不是條件，所以空窗中的角色照樣可以設名額，只是不能挑人。
3. **找到對方**：在自己的世界走出對方的代號，開白光傳送門過去，沿路看對方的規則建築，走到終點。
4. **那一微秒判定**：
   - **雙方規則表只要有一方通，就能對接。**
   - 任一方的規則表打開「要求兩方都通」，就要兩方都通。
   - 任一方打開「對方一定要接受我的村規」，對方沒接受就沒有對接資格。
   - 對方在空窗期：只能以「做不到對方規則表的要求」拒絕；空窗角色自己的兩個開關都視為關閉。
5. **互給點數**：對接成立後，A 拿到 B點，B 拿到 A點。給多少各自決定，但不能超過自己當天還剩的點。**平台禁止預支**：今天的點只能今天給，不能先給明天以後的點。不能存（隔天歸零）、也不能借，點數永遠只代表「今天這個人」，平台裡永遠沒有欠款。
6. **留紀錄**：對接紀錄記下雙方角色、時間、各給了多少點。角色就是版本，所以紀錄本身就說明了雙方接受的是哪一套規則。

### 聯絡

- 平台不做文字訊息功能。
- **聯絡方式欄**：主人自己填（電話、LINE ID、Email，或不填）。**只有預約成功的人看得到**；對接結束或角色週期結束後自動隱藏。要不要暴露真實身分由每個人自己決定。

## 6. 點數帳與兌現

- 點數帳：誰手上有誰的點、多少、從哪一次對接拿到的。
- **兌現**：拿著 A點，照 A 的資源表向 A 換東西。A 在空窗期時暫停兌現；A 的週期結束後，A點作廢。
- 每筆點數保留簽章欄位，多人版由發出者簽章，沒人能冒用別人發點。

## 兌現失敗

- A 付不出點數能換的東西 = A 的資源已經不夠維持這個角色，所以**兌現失敗，A 自動進入空窗期**。這不是懲罰，是如實反映事實。
- 兌現失敗留下公開紀錄（誰拿多少 A點、什麼時候來換、沒換到）。
- 空窗中：A 每天的點停發（不能再發沒有東西撐腰的點）；別人手上的 A點暫停兌現、不作廢；A 只能以「做不到對方規則表的要求」拒絕對接。
- **A 補足資源、兌現欠的那一筆，空窗才結束**，恢復原本的角色。
- 空窗中也不能提早結束來逃：提早結束本來就要先讓持有人兌現或同意。
- A 的週期時鐘照走；一直沒恢復、週期到了，A點作廢，持有人拿不回東西。拿一天的能量換別人的點是投資，投資本來就可能失敗；持有人對接時看得到 A 的結束時間和兌現失敗紀錄，風險自己評估。

## 村規怎麼運作

- **平台只做三件事：記事實、全部公開、不替任何人執行承諾。**
- 村規是建立在這些公開事實上的約定。例：A 的村規寫「我願意預支，承諾給你 5000 點，分三天給」，平台看到的只是三次普通對接（每次都不超過當天的點）；三次合起來是在履行承諾，這件事由村規和信用處理，平台不管。違約的代價是大家都查得到的紀錄，不是平台處罰。
- 所以冒險可以存在，但它是人對人的承諾，不是平台裡的點數。
- **村規系統是另外的程式，只讀平台的公開資料**（對接紀錄、規則表、資源表、點數帳的公開部分），用來算自己的東西（例如東恆村規的題點、戰點、難題、融合），記在自己的帳上。
- **村規系統只能讀、不能寫**：不能替平台產生點數，也不能突破每天的上限。這是底層邏輯的保險。
- 平台要做到的只有：資料公開、格式固定、查得到。

## 7. 3D 裡世界（一定保留）

裡世界存在的理由：**走進一個人的世界，看得見他的規則建築，就能瞭解他的規則。**

- 角色序號、走代號、白光傳送門、功能點外觀自由、內部空間、世界只能是資料：沿用 v5 的做法，細節見 [VILLAGE-donghen.md](VILLAGE-donghen.md) 的對應章節。
- 平台的功能點：

| 功能 | 對應 | 預設外觀（可改） |
|---|---|---|
| 規則 | 規則表（我的點能做什麼、對接條件、村規） | 屋 |
| 資源 | 資源表、兌現 | 市集 |
| 終點 | 對接時間，對接在這裡發生 | 台 |
| 角色 | 每天的點、生命週期、狀態（活著／空窗） | 碑 |
| 點數 | 點數帳（只有自己看得到） | 帳房 |
| 地標 | 沒有功能，用來走代號 | 自由 |

- 規則、資源、終點、角色**一律公開**；點數帳只有自己看得到。
- 村規想在世界裡表現成建築，可以用地標加內部空間自己蓋，平台只負責顯示。

## 8. 表世界

活頁簿格式沿用 v5（一張表一頁、欄字母、列號、凍結首欄、連結跳轉）。頁面順序：

**下一步｜查詢｜角色｜規則｜資源｜世界｜走法｜對接時段｜對接紀錄｜點數｜兌現**

## 9. 資料存放（三層，玩家自己選）

| 方式 | 玩家要做什麼 | 適合誰 |
|---|---|---|
| **平台代管（預設）** | 什麼都不用做，註冊就能玩 | 大部分人 |
| **存到自己的雲端硬碟** | 第一次授權，之後自動存 | 在乎資料在自己手上的人 |
| **自己架** | 放到自己的網站空間 | 會技術、想完全掌控的人 |

- 3D 世界、規則表、資源表本來就公開，放平台沒有隱私問題；一個世界只是幾 KB 的資料。
- **敏感資料（例如聯絡方式）端對端加密**：平台只幫忙傳，自己讀不到；只有預約成功的人能解開。
- 資料格式公開，想自己存、自己架的人隨時能搬走，不被平台綁住。
- 不管存在哪裡，**世界只能是資料，不能是程式**：讀別人的世界只讀資料，畫面由自己的程式畫。

## v6 實作備註

照上面的定案做在 `v6/`（見 [PLAN-v6.md](PLAN-v6.md)）。實作上補的決定：

- **主人那一方給多少**：單機版主人不在場，所以開對接時段時就填「每次給多少點」，對接那一微秒以當天剩下的為上限自動扣；來的人站在終點上時自己填要給多少。
- **提早結束的同意**：單機版持有人都在本機，「結束並重創」視為持有人都同意；多人版要真的收同意。
- **聯絡方式**：預約成功、還沒對接完的那個時段期間看得到；對接完或主人結束就隱藏。
- **草稿**：建角色先開草稿（名字、每天的點、週期、規則、資源、聯絡方式），按「創角色」才寫進角色表並算 `rulesHash`；之後規則頁只有「結束並重創」，重創的草稿帶著原規則和前身。
- **兌現失敗自動空窗**：規則函式丟出錯誤前已經把角色改成空窗、記下欠的那一筆；表世界失敗時也存檔重畫，所以紀錄立刻公開。
- **空窗角色的拒絕**：`canRefuse(owner, visitor)` 只在「主人在空窗、而且主人不通預約者的條件（做不到對方的要求）」時成立；其他情況一律不能拒絕（不在空窗的主人靠規則表的條件擋人，不能手動拒絕）。對接時段頁只在這種情況才出現「拒絕（做不到對方的要求）」按鈕；拒絕後預約拿掉、留公開紀錄。
- **規則層也守那一微秒**：`dock()` 只接受時段那一微秒的判定：`atUs` 要在 `[slot.atUs, slot.atUs + 1 秒)` 內（畫面層每 50 毫秒判一次，那一微秒的結果在下一格送進來）；超過就標為錯過、丟錯誤，之後這個時段不能再對接。`expire()` 每格清算：過了判定窗還沒對接的預約全部標為錯過，留紀錄。
- **功能點 id**：預設世界的物件 id 帶序號（例如 `rule_00000000001`），避免不同角色的世界互相撞名。
- 門的可見條件只有「所有人／只有自己」（沒有「融合過的人」，那是村規的概念）。

## 待確認
